# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

FisioApp — a mobile-first web app (accessed by link) that walks orthopedic-knee patients through guided physiotherapy: per-phase exercise protocols, session execution with pain/difficulty logging, progress charts, badges, and an AI Doctor chat. **Current focus is ACL/LCA** — the meniscus and patellofemoral protocols exist in code but are flagged "em breve" in onboarding. The LCA protocol mirrors the official clinical booklet (`../docs/FINALIZADA - CARTILHA DE LCA .pdf`): weeks 1→24 with ROM (ADM) targets, functional milestones, and the alert triad (pain/swelling/instability + Lag sign). **All clinical data is mock** (`src/data/`); there is no real backend or auth yet. State lives in a localStorage-persisted Zustand store. Generated by [Lovable](https://lovable.dev); UI text is Brazilian Portuguese.

> **Not a PWA** despite what product docs say — there is no manifest/service worker. It's an SSR app with SPA build mode enabled (`vite.config.ts`), which also feeds the future **Capacitor** native packaging. Keep code **web-first, native-aware**: nothing on the critical path may depend solely on SSR; the AI `/api/chat` and any future backend must be reachable as remote HTTP (client SDK), not SSR-coupled server functions.

> **Workflow (see the workspace `../../CLAUDE.md`):** engineering is 100% local (single writer); GitHub `main` is the source of truth. Lovable = Publish (hosting) + AI gateway for the coach during validation; the real data backend will be **our own Supabase** (never Lovable Cloud), gated until after pilot validation (LGPD). Lovable writes build-config commits to the repo on publish, so **always `git fetch` + `git merge --ff-only origin/main` before pushing**.

> The parent `SPEC.md` describes an _earlier intended_ stack (Vite + React Router + Supabase, "no localStorage for clinical data"). Implementation diverged: TanStack Start, TanStack Router, localStorage. Trust the code here over that doc for stack; use it for screen/model reference.

## Commands

Package manager is **Bun** (`bun.lock`, `bunfig.toml`).

```bash
bun install
bun run dev        # vite dev — SSR dev server
bun run build      # vite build (nitro, Cloudflare target by default)
bun run preview    # preview production build
bun run lint       # eslint .
bun run format     # prettier --write .
```

No test runner is configured. Type-checking happens via the editor / build (`tsc --noEmit`-style config in `tsconfig.json`); there is no standalone `typecheck` script.

The AI Doctor chat requires `LOVABLE_API_KEY` in the environment (read server-side in `src/routes/api/chat.ts`). Without it, `/api/chat` returns 500 but the rest of the app works.

## Architecture

**TanStack Start (SSR) + TanStack Router file-based routing + React 19 + Tailwind v4 + Vite 7.**

### Routing (`src/routes/`)

File-based. `routeTree.gen.ts` is **auto-generated — never edit by hand**. Naming is flat-with-dots, not nested folders:

- `__root.tsx` — app shell (HTML, head, QueryClientProvider, error/404 boundaries). Keep `<Outlet />`.
- `_app.tsx` — layout for the authenticated app: wraps pages in `MobileFrame` + `BottomNav`, gates on hydration, redirects to `/welcome` when not onboarded. All `_app.*.tsx` routes render inside it.
- `_app.session.$sid.exercise.$eid.tsx` — dynamic params use bare `$` (`$sid`, `$eid`), no curly braces.
- `index.tsx`, `welcome.tsx`, `onboarding.tsx`, `onboarding.treatment.tsx` — pre-app flow (outside `_app`).
- `api/chat.ts` — server route (AI streaming endpoint).
  See `src/routes/README.md` for the full convention table. Do **not** create `src/pages/` or `app/layout.tsx` (Next/Remix conventions don't apply).

### State (`src/store/patient.ts`)

Single Zustand store (`usePatientStore`) with `persist` middleware → `window.localStorage` key `fisiocare-patient-v2` (schema `version: 3`, with a `migrate` fn — bump both when changing persisted shape). Holds the user, treatments, active treatment, onboarding draft, and the core `completeSession()` reducer that recomputes phase progression, streaks, adherence, pain history, weekly frequency, and unlocked badges.

**SSR hydration is manual.** The store uses `skipHydration: true` and a no-op storage on the server. Any component reading patient state must gate on `useHydratedStore()` (calls `persist.rehydrate()`) to avoid SSR/client mismatch — see `_app.tsx`. Don't read store data during the un-hydrated render.

### Domain data (`src/data/`)

`protocols.ts` (3 injury protocols → phases → exercises), `badges.ts`, `mockUser.ts` (seed treatments). All TypeScript interfaces live in `src/lib/types.ts`. The store derives everything (current phase, today's session, ordered exercises) from these via selector helpers exported at the bottom of `patient.ts`.

### AI Doctor (`src/components/support/` + `src/routes/api/chat.ts`)

Uses the Vercel AI SDK (`ai`, `@ai-sdk/react`) streaming to a server route that proxies the **Lovable AI Gateway** (OpenAI-compatible, `src/lib/ai-gateway.server.ts`, model `google/gemini-3-flash-preview`). The client passes a `treatmentContext` block that gets injected into the system prompt. The system prompt enforces clinical guardrails (no prescriptions, escalate red-flag symptoms) — preserve these when editing.

### UI

shadcn/ui ("new-york" style) components in `src/components/ui/` — generated, generally don't hand-edit. Icons: **lucide-react**. Charts: **recharts** (`src/components/progress/`). Feature components grouped by domain: `session/`, `progress/`, `treatment/`, `support/`, `layout/`, `celebration/`. The whole app renders inside `MobileFrame` (a phone-sized viewport). Path alias `@/` → `src/`.

## Critical gotchas

- **Vite config is Lovable-managed.** `vite.config.ts` wraps `@lovable.dev/vite-tanstack-config`, which _already_ bundles tanstackStart, viteReact, tailwindcss, tsConfigPaths, nitro, the `@` alias, and error loggers. **Do not add these plugins manually** — duplicates break the build. Extend via `defineConfig({ vite: { ... } })`.
- **Server-only code uses the `.server.ts` suffix** (`config.server.ts`, `ai-gateway.server.ts`) so Vite keeps it out of the client bundle. Never import a `.server.ts` file from a client component.
- **Read env inside handlers, not at module scope.** The Cloudflare Workers build binds env per-request; `const x = process.env.X` at module top resolves to `undefined`. See the note in `config.server.ts`.
- **Public env vars need the `VITE_` prefix** and reach the browser — never put secrets there.
- **Supply-chain guard:** `bunfig.toml` sets `minimumReleaseAge = 86400` (skips packages published <24h ago). To install a brand-new version, it must be added to `minimumReleaseAgeExcludes` — confirm with the user first.
- **Error handling is layered** (`server.ts` normalizes h3-swallowed SSR 500s, `start.ts` middleware, `__root.tsx` boundaries, `lib/error-capture.ts`, `lib/lovable-error-reporting.ts`). When touching SSR/error flow, account for all layers.
- Formatting: Prettier (`printWidth: 100`, double quotes, semicolons, trailing commas). Run `bun run format` before finishing.
